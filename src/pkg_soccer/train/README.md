# 训练套件（2v2，41 维观测：队友 + 双对手）

目标：用 2D 运动学仿真 + PPO 训练"高层速度策略"，导出成
`pkg_soccer/policy_*_actor.npz`，由部署端 `rl_control.py` 原样加载。

**观测是 41 维**：前 29 维与旧的 1v1 完全一致，后面多出"队友"（29-34）和
"次近对手"（35-40）两个 6 维块。29 维权重继续可用（1v1），41 维权重才带队友感知。

## 目录

| 文件 | 作用 |
|---|---|
| `team_env.py` | 2v2 规则对齐环境（场地/门/死区/9 发球点/僵持 8 s/复位/刚体断流） |
| `obs.py` | 23/29/41 维观测构造，逐位对齐 `rl_control.observation` |
| `track.py` | 部署端 `Track` 的副本（训练机没装 ROS 包时使用） |
| `scripted.py` | 脚本队友/对手，角色化：`attacker`（绕球推射）/ `support`（守位、危险回追） |
| `peer.py` | 用历史 npz 权重当队友/对手；`PeerPool` 做对手池 |
| `train_ppo.py` | sb3 PPO 训练（tanh 挤压高斯，与部署端同构） |
| `selfplay.py` | 交替自博弈：进攻狗 → 防守狗 → 换权重再训 |
| `export_actor.py` | 训练模型 → 部署 npz，并做确定性前向一致性检查 |
| `verify.py` | 自检：观测契约（29 与 41）、环境冒烟、npz 前向 |
| `eval_match.py` | 按 4 min 半场评估（默认同时控本队两只狗） |

## 3. 训练

```bash
# 从旧 29 维权重热启动（第一层前 29 列照抄、新增 12 列置 0，初始行为与旧策略等价）
python -m train.train_ppo --role attacker --obs-dim 41 \
  --init pkg_soccer/policy_duel_attacker_actor.npz \
  --no-randomize --steps 500000 --envs 8 --out runs/a41_probe

# 正式训进攻狗
python -m train.train_ppo --role attacker --obs-dim 41 --steps 5000000 --envs 8 --out runs/a41

# 训防守狗：队友与对手都换成刚训好的进攻权重（自博弈）
python -m train.train_ppo --role defender --obs-dim 41 --steps 5000000 --envs 8 \
  --peer-teammate runs/a41/policy.npz --peer-opponents runs/a41/policy.npz --out runs/d41

# 一键交替自博弈（自动训练→导出→换权重→再训练，最后落到 pkg_soccer/policy_2v2_*.npz）
python -m train.selfplay --rounds 4 --steps 1000000 --envs 8
```

课程建议：

1. `--no-randomize` 跑 50 万步，确认奖励/判定没写错（应能看到稳定进球）；
2. 开随机化（默认）跑 500 万步；
3. 换 `--peer` 让队友/对手变成历史权重，进入自博弈阶段；
4. 防守狗从 `--role defender` 开始，`--peer-teammate` 用同队进攻权重，保持"一攻一守"。

**为什么只训一只狗**：sb3 是单智能体实现。两狗共用权重做联合 rollout 需要自造
多智能体采样器；"我 vs 上一版的我、队友也是上一版的我"这种交替自博弈在同等算力下
能拿到相近的协作行为，而且完全复用现有验证/导出链路。

## 8. 观测槽位约定（41 维）

| 索引 | 内容 |
|---|---|
| 0-22 | 基础 23 维（球/球门/自身速度/上步动作/四墙/接触/年龄） |
| 23-28 | 最近对手：相对位置 /3、相对速度 /2、相对朝向 sin/cos |
| 29-34 | 队友：同上 |
| 35-40 | 次近对手：同上 |

- 对手按狗到对手距离升序填入；最近对手是**硬要求**（缺失则等待，不输出指令）。
- 队友/次近对手**可缺**：未配置、断流、轨迹不连续 → 该 6 维整块填 0
  （合法朝向 `sin²+cos²=1`，所以 `(0,0)` 可辨识为"看不到"）。
- 训练端 `--body-dropout`（默认 0.05，粘滞约 0.3 s）模拟这种断流。

## 9. 已知近似与限制

1. **没有模拟 15 s 暂停**：进球后环境立即复位；实际比赛由场边流程负责暂停/复位。
2. **观测时延用 age 字段近似**：位置不做延迟队列，只把 age 设为 `(0.5+obs_delay)·dt`。
3. **对手槽位按距离排序**：两只对手几乎等距时 `23-28` 与 `35-40` 会互换，
   策略不做身份跟踪（训练分布里同样存在）。
4. **脚本队友较弱**：单只脚本狗贴球后容易原地打转，只适合第一轮陪练；
   跑完第一轮就切 `--peer` 用权重当队友/对手。
5. **不允许 VecNormalize**：部署端没有归一化统计量；训练必须保持原始观测 + clip ±5。
6. **维度必须匹配**：41 维权重只能喂 41 维观测；`Actor` 与 `peer.py` 都会显式校验。

## 11. 观测"性价比"实测（消融工具）

问题：给每个刚体多送 6 维（位置 + 速度 + 朝向）到底值不值？答案是**分项差别很大**，
而且"维度成本"几乎为零、真正的成本是训练能否利用。

### 11.1 工具

```bash
# 1) 输入敏感度：训练好的策略到底读不读这几位（有限差分，秒级）
python -m train.sensitivity --model runs/w_full/policy.npz --steps 400

# 2) 行为消融：训练/评估时把某项信息抹成常量（维度不变，契约不变）
python -m train.ablation \
  --case "A 完整=runs/w_full/policy.npz|" \
  --case "B A遮速度=runs/w_full/policy.npz|body_vel" \
  --case "D 训练遮速度=runs/w_no_vel/policy.npz|body_vel" \
  --seeds 0,1,2 --halves 2
```

消融名：`body_vel`（三只刚体相对速度归零）、`body_yaw`（相对朝向固定同向）、
`teammate` / `opponent2`（整块归零，等价"看不到这只狗"）、`opponent.vel` 这类单项。
训练时用 `--ablate` 让整个训练/评估共用同一套遮蔽。

### 11.2 实测结果（本机，40 万步热启动微调，3 种子 × 2 个 4 min 半场）

| 配置 | 球推进 | 贴球率 | 最近率 | 进球/场 | 结论 |
|---|---|---|---|---|---|
| A 完整 41 维 | 2.33 m | 56.8% | 56.6% | 5.00 | 基线 |
| B 训练有速度、推理遮掉 | 2.37 m | 56.5% | 53.8% | 4.67 | **对手速度方向边际收益 ≈ 0** |
| C 推理遮队友块 | 2.27 m | 57.2% | 55.4% | 4.00 | 有损失，但不致命 |
| D 训练期遮速度 | **-0.85 m** | 73.9% | 62.5% | 0.50 | 崩：旧权重行为依赖这 2 维 |
| E 训练期遮朝向 | **-1.66 m** | 69.7% | 61.4% | 0.00 | 最崩 |
| F 训练期遮队友块 | 0.36 m | **77.0%** | 76.5% | 1.67 | 抢到球却打不出配合 |

读法：

1. **B≈A**：微调完成后，把对手/队友速度全部遮掉，进球从 5.00 掉到 4.67（噪声级）。
   说明在"抢球→推射"这个技能上，球速 + 相对位置已经够用，对手速度方向是锦上添花。
2. **D/E 反而崩**：因为热启动的 29 维旧权重本身依赖这几位（敏感度实测：
   最近对手速度 3.5%、朝向 4.9%，都高于其位置的 0.9%），一抽掉旧行为就散。
   所以**这 2 维不要砍**——它们是热启动能站住的原因，砍了要用几倍算力重学。
3. **F 最值得警惕**：遮掉队友块后贴球率反而最高（77.0%），但球推进 0.36 m、进球 1.67。
   这就是"两只狗挤同一个球"：看不见队友 → 会抢球，但不会配合。
   → **队友块 6 维是 41 维里性价比最高的一块。**

### 11.3 速度方向的可靠性（决定"值不值"的物理前提）

`Track` 用 0.1 s 窗回归速度。0.008 m 动捕噪声下实测：

| 球/狗真速 | 速度误差 | 方向误差 |
|---|---|---|
| 0.50 m/s | 0.086 m/s | 5° |
| 0.30 m/s | 0.103 m/s | 13° |
| 0.15 m/s | 0.103 m/s | **30°** |

低速段方向基本是噪声。所以：

- **不要把速度拆成"方向单位向量 + 速率"**：那是 3 维，比现在的 `(vx, vy)` 2 维更贵，
  信息还等价，且强迫网络把"不可靠的方向"当成独立通道；
- 保留 `(vx, vy)`（含幅值）让网络自己决定低速时信多少，是最省的做法。

### 11.4 结论：钱该怎么花

| 想加的东西 | 成本 | 实测/推断收益 | 建议 |
|---|---|---|---|
| 相对速度 `(vx, vy)` | **0 维**（已在块内） | 热启动依赖，防守/快对手需要 | 保留 |
| 方向单位向量 + 速率 | +1 维（3 替代 2） | 信息等价、更贵 | 不加 |
| 队友块（6 维） | 已加 | 5.00 → 1.67 球/场（遮掉时） | **最高优先，别省** |
| 最近对手 0.5 s 预测位置 | +2 维（只给最近对手） | 未测，理论上限 ≈ B 的差距 | 下一步可选 |
| 三只狗都加预测位置 | +6 维 | 同上，但收益不随数量线性 | 不划算 |

### 11.5 一个比加维度重要得多的坑

从零训练（不给 `--init`）40 万步会**塌缩成饱和常量**：实测贴球率 0.000、
球推进 -0.11 m，策略输出 `vy` 饱和在 0.70、一路退到角落。
把死球惩罚从 -3 改成 0 只把贴球率抬到 0.019，说明主因不是惩罚，而是探索不足 + tanh 饱和。

**结论：必须从 29 维旧权重热启动**（`--init pkg_soccer/policy_duel_attacker_actor.npz`），
或者先把 `--no-randomize` 跑通再开随机化。这条比纠结多加 2 维重要一个数量级。

## 12. 奖励函数（含 2026-11-16 新增的三项：默认关闭）

`train/team_env.py::_reward`，全部按**队**结算：同队两只狗永远拿到同一个数
（`reward[i] = team_reward[TEAM_OF[i]]`），所以"谁碰球"不影响分配 —— 这就是
"同队两狗持球时等价"的实现方式（原本就是这样，本轮只是把它显式化）。

| 项 | 默认 | 说明 |
|---|---|---|
| 每步 | −0.005 | 催促尽快结束 |
| 势能整形 | 开 | `γΦ(t+1) − Φ(t)`，`Φ = 1.5×球到门距离 + 0.8×双狗到"球后点"平均距离`；potential-based，不改最优策略 |
| 新触球 | +0.5 | 首次进入 0.43 m 触圈（每只狗各计），实测一个半场约 15 次 ≈ +7.5 |
| **团队控球** | **0（关）** | `--reward-possess`：球在**对方半场**且本队持球时 +x/步，按队给 |
| **半场推进** | **0（关）** | `--reward-half`：`±x × (球前向位置/5) /s`，球在己方半场为负 |
| **无球干扰** | **0（关）** | `--reward-press`：对方在**对方半场**持球时，我方非持球狗到持球者的距离 <1.5 m 得 `1−d/1.5`，取最贴近的一只 |
| **远离死区** | **0（关）** | `--reward-edge`：势能项 `Φ += w × min(1, 球到最近危险边界的距离)`，危险边界 = 两侧边线 + 门宽外的端线（门前中路不罚）。`γΦ'−Φ` 结算，**不改最优策略**，只在离边线约 1 m 内给梯度。试 0.8~1.5 |
| 进球 / 失球 | +10 / −10 | |
| 死球 / 出界 | −3（最后触球方）；无触球两队各 −1.5 | |
| 僵持（8 s） | −2 | |
| 碰撞 | −0.03/步 | |

### 12.1 为什么这三项默认是关的（实测）

同一套热启动权重、同样 30 万步、3 种子 × 2 个 4 min 半场：

| 奖励配置 | 球推进 | 控球率 | 进球/场 | 失球/场 | 死球/场 |
|---|---|---|---|---|---|
| **旧奖励（基线）** | **2.33 m** | 50.1% | **5.00** | 0.00 | 9.3 |
| 只加推进（half 0.4） | −0.85 m | 42.9% | 0.67 | 0.17 | 4.8 |
| 推进 0.4 + 控球 0.01（不加干扰） | −0.80 m | 70.4% | 0.83 | 0.67 | 11.0 |
| 三项全开（0.4 / 0.01 / 0.01） | 0.32 m | 63.0% | 0.00 | 0.00 | 12.7 |
| 三项调低（0.15 / 0.002 / 0.003） | 1.97 m | 62.0% | 2.17 | 0.17 | 12.7 |
| 三项半场门控（0.15 / 0.004 / 0.004） | 1.63 m | 57.2% | 2.67 | 0.00 | 11.0 |

三条原因（都能从数字里读出来）：

1. **稠密项的单集累积量和进球同量级**：0.01/步 × 600 步 = 6 分，控球+干扰合计 12 分，
   而进球只有 10 分。于是"抱球盘带 + 贴人"变成比进球更划算的策略 —— 控球率从 50%
   升到 70%，球推进却从 +2.33 m 掉到 −0.80 m（在自己半场抱着球刷分）。
2. **推进项与已有势能重复**：`Φ` 里的 `1.5×球到门距离` 已经是单调的推进激励，
   再加一个位置项属于重复激励，而且它是非势能项（会改最优策略），净效果是扰动。
3. **过程奖励 vs 结果奖励**：这三项奖励的都是"过程"，在 30 s 短幕 + 弱脚本对手下，
   策略更愿意守住过程分，不愿冒射门失败的风险。死球数从 9.3 涨到 11~12.7，
   说明它开始把球往边线死区带。

### 12.2 如果一定要用，怎么用

- 先按 §3 把"抢球+射门"用**旧奖励**训到稳（这是目前唯一验证过能出 5 球/半场的配置）；
- 想强调进攻，**不要加位置项**，把 `shaping_ball` 从 1.5 提到 2.0~2.5（仍是势能项，安全）；
- 想做协作/干扰，用**半场门控 + 小权重**：`--reward-possess 0.004 --reward-press 0.004`
  （只在"进攻方在对方半场组织"时结算），并把训练预算提到 500 万步以上再判断；
- 判断标准别只看进球，同时看 §11 的 `控球率 / 干扰距 / 死球数` —— 本轮就是靠这三个指标
  发现"控球率涨了但球往后跑"的。

## 13. 短程传球可行吗（`python -m train.passing` 实测）

结论：**在"只用走位速度顶球"的动作空间里，短传基本不成立**。

测得的事实（仿真物理，狗以动作饱和速度 0.45 m/s 正面顶球）：

| 恢复系数 e | 摩擦 a | 出脚球速 | 滚到静止的距离 |
|---|---|---|---|
| 0.3 | 0.8（典型） | 0.54 m/s | 0.22 m |
| 0.5 | 0.8 | 0.63 m/s | 0.28 m |
| 0.7 | 0.8 | 0.72 m/s | 0.36 m |
| 0.7 | 0.3（最理想） | 0.75 m/s | 0.96 m |

把球送到 d 米需要的出脚速度是 `sqrt(2·a·d)`：0.6 m 就要 0.98 m/s（a=0.8），
比顶球能给出的 0.75 m/s 还高。**所以传球距离被卡在 0.3~0.4 m，等于没有传球**，
这也解释了为什么现在学到的都是"贴脚带球"。

要让传球成立，最小改动是给一个 **kick 通道**：

- 真机 `push` 模式已有 1.5 m/s × 450 ms 脉冲（见训练指南 §17），球出脚约 2.2 m/s，
  对应滚距 3 m（a=0.8）—— 1~3 m 的短传是够的；
- 训练侧需要：**动作 +1 维**（触发 kick）＋**观测 +1 维**（kick 冷却/可用标志），
  奖励加"接球成功"（球被队友首次触碰，且位移 > 0.5 m）；
- 精度：站位横向误差 5 cm → 出脚方向偏 10° → 1 m 处偏 0.18 m、2 m 处偏 0.36 m；
  接球圈 0.43 m，所以 **2 m 以内的短传在动捕噪声下可行，再远就需要更准的站位**。

建议顺序：先按当前动作空间把 2v2 抢球/射门训稳（本 README §3），再决定是否为传球
扩动作空间——扩了就要重训，且真机要走 `push` 脉冲链路，属于一次结构性改动。

## 14. 提速与高速短冲推球（2026-11-16 实测）

需求：把狗跑快（现在前进上限 0.45 m/s），再加"高速短冲推球"。
结论先放这儿：**机制已经做好并验证同源，但这一轮的权重不要上狗** ——
提速在"对手也很快"时换不到进球，短冲能提高进球但把自伤死球推到 2~3 倍。

### 14.1 机制怎么落地（换 npz 就能换档，不改代码）

| 层 | 改动 |
|---|---|
| `pkg_soccer/rl_control.py` | `Actor` 读 **npz 里的 `action_scale`**（档位随权重走）；`rl_speed_limit:=0` 表示跟随权重；新增 `_dash()` 短冲 |
| `pkg_soccer/soccer.py` | 新参数 `rl_dash / rl_dash_speed / rl_dash_ms / rl_dash_cooldown / rl_dash_goal_cone`；启动日志打印档位并告警"高速档没开短冲" |
| `train/team_env.py` | `EnvConfig(action_scale=..., dash=..., dash_goal_cone=...)`；`_dash_commands` 与部署端逐条同规则；**修掉 `prev_action` 从不写入的 bug**（见 14.5） |
| `train/train_ppo.py` | `--speed-scale k`（动作缩放 = [0.45,0.20,0.70]×k，转向不变）、`--dash`、`--dash-goal-cone`；热启动时输出层按 `旧档/新档` 缩放；结束写 `train_config.json` |
| `train/export_actor.py` | `--speed-scale` 或 `--config train_config.json`，把档位写进 npz |
| `train/ablation.py` / `eval_match.py` | 自动读 npz 的档位 + 同目录 `train_config.json` 的短冲配置；`--scripted-speed` 可把对手也提速 |
| `train/speed.py`（新） | 速度档诊断：单次推球、带球推进速率、控制代价、死球风险 |
| `train/matchup.py`（新） | 两队都用真权重对打（**有已知测量缺陷，见 14.4**） |
| `train/verify.py` | 新增 `--speed`：档位读取、上一动作槽位、短冲两侧同源 |

档位换算（`--speed-scale`）：

| k | 前进缩放 | 限速 | 相当于 |
|---|---|---|---|
| 1.0 | 0.45 m/s | 0.50 | 现在上机的 41 维权重 |
| 1.5 | 0.68 | 0.75 | 中速 |
| 2.0 | 0.90 | 1.00 | "高速档"（本轮实验用） |
| 3.3 | 1.49 | 1.65→协议 1.5 | 协议上限 |

转向在任何档位都保持 0.70 rad/s —— 提速不提转速，否则 20 Hz 下会甩头丢球。

### 14.2 物理上提速能买到什么（`python -m train.speed`）

| 档位 | 单次顶球出脚 | 滚距 | 连续带球推进 | 跨半场 | 追球 2 m | 过冲(最坏) |
|---|---|---|---|---|---|---|
| 0.45 | 0.64 m/s | 0.32 m | 0.16 m/s | 11.1 s | 4.4 s | 0.18 m |
| 0.68 | 0.98 | 0.71 | 0.38 | 7.4 | 3.0 | 0.27 |
| 0.90 | 1.31 | 1.30 | 0.60 | 5.6 | 2.2 | 0.36 |
| 1.22 | 1.79 | 2.37 | 0.90 | 4.1 | 1.6 | 0.49 |
| 1.49 | 2.19 | 3.55 | 1.06 | 3.4 | 1.3 | 0.59 |

**短冲（1.5 m/s × 450 ms）在任何档位都给 2.2 m/s 出脚、3.5 m 滚距** —— 也就是说
"射门力度"由短冲决定，跟档位无关；档位只决定"跑位速度"。

物理收益很明确（跨半场 11.1→5.6 s、带球推进 0.16→0.60 m/s），**但代价也在这里**：
0.90 时单次顶球就滚 1.30 m，而距围挡 0.8 m 就是死区。所以"提速=更容易把球推进死区"。

### 14.3 行为实测（单边同分配，受控 0 号狗，其余脚本）

对手 0.30 m/s、5 种子 × 2 个 4 min 半场：

| 配置 | 档 m/s | 短冲 | 球推进 | 控球率 | 进球/场 | 失球/场 | 死球/场 |
|---|---|---|---|---|---|---|---|
| 旧基线（当前能用的 41 维） | 0.45 | 关 | **2.55** | 0.377 | **4.90** | 0.00 | 11.1 |
| A 0.45（同权重重训，含 prev_action 修复） | 0.45 | 关 | 1.85 | 0.441 | 3.00 | 0.00 | 7.3 |
| E 0.90 + 门控短冲（52°） | 0.90 | 开 | 1.69 | 0.345 | **5.00** | 0.20 | 23.5 |
| C 0.90 + 无门控短冲 | 0.90 | 开 | 1.35 | 0.374 | **6.60** | 0.50 | **36.3** |

对手也提到 0.90 m/s（模拟"对手一样快"）：

| 配置 | 进球/场 | 失球/场 | 死球/场 |
|---|---|---|---|
| 旧基线 0.45 | 4.83 | 0.00 | 8.2 |
| A 0.45 | 3.00 | 0.17 | 9.3 |
| E 0.90 + 门控短冲 | 5.00 | 1.17 | 28.5 |
| C 0.90 + 无门控冲 | 4.17 | 1.17 | 39.8 |

三条可执行结论：

1. **纯提速不划算**：0.90 档（B/F，300k 与 600k）球推进从 1.85 掉到 0.66~0.69，
   死球翻倍到 17.8~25.7，进球还低于基线。多训一倍步数（600k）也没救回来。
2. **短冲是唯一能提高进球的开关**，但每个进球要多付 3 次自伤死球（见 14.4 归因）。
   门控（只朝对方球门冲，52°）能把死球压 35%，代价是进球从 6.6 回到 5.0 ≈ 基线。
3. **对手一样快时，提速的优势消失**（E 5.00 vs 基线 4.83，但开始丢球 1.17）。
   单边评估里看着"提速很猛"，是因为对手脚本只有 0.30 m/s。这条是本次最重要的提醒：
   **速度的价值取决于对手速度，不是绝对值。**

### 14.4 死球归因（决定"值不值"的关键数字）

3 种子 × 2 半场，按"死球前最后触球队"归因：

| 配置 | 我方触球导致死球 | 对方触球导致 | 进球 | 每个进球摊到的自伤死球 |
|---|---|---|---|---|
| 旧基线 0.45 | 44 | 15 | 33 | 1.3 |
| A 0.45 | 31 | 11 | 17 | 1.8 |
| E 0.90+门控冲 | 131 | 17 | 34 | 3.9 |
| C 0.90+无门控 | 191 | 10 | 46 | 4.2 |

高速/短冲时 88%~95% 的死球是**我们自己**把球推进死区。4 min 半场里 30 次停球
（裁判摆球）等于把比赛节奏全丢了，所以这不能只看"进球多了 1.7 个"。

### 14.5 顺带修掉的一个观察契约 bug

原 `TeamEnv.step` 从不写 `self.prev_action`，导致训练时**观测 9-11（上一动作）
恒为 0**，而部署端 `RLController.command` 写的是真实的 `velocity/scale`。
即"训练看到的 41 维"和"上狗看到的 41 维"有 3 维分布不同。现已修正
（`prev_action = 限速/冲刺后的 cmds / action_scale`，与部署端同式），`verify --speed`
会锁死这条。

代价要如实说：同一批 300k 微调，修好之后进球 4.90 → 3.00，说明旧权重其实是
"靠这个槽位一直为 0"跑起来的。**修是对的（部署端本来就在喂真值），但需要更长预算。**

### 14.6 建议的下一步（按性价比排序）

1. **先别换高速权重上狗**。现在的 0.45 权重仍是唯一有 5 球/半场证据的策略。
2. 想让球跑得快：**短冲比提速便宜**（短冲只贵 450 ms，档位要整场都变）。
   但要把自伤死球压下去，先给奖励加一项"球到最近死区的距离"势能项
   （和 `shaping_ball` 同类，势能项不改最优策略），再跑 500 万步。
3. 想真正提速：把 `--speed-scale 2.0 --dash --dash-goal-cone 0.9` 用 500 万步训练
   （约 2 h/50 万步 → 单卡 CPU 约 1.8 h/500 万步），并且**用 `--peer-opponents`
   换成同样快的权重**，否则又是在打 0.30 m/s 的假对手。
4. 对打评估（`train/matchup.py`）暂时不能当判据：这些策略只在"进攻 +X"上训过，
   作为 1 队会明显变差（自对自 `rwd_old` 26:0、`sp_a` 9:5）。修法是给 1 队做
   横轴镜像观测 + 侧向动作反号，属于结构性改动，另开一轮再做。

### 14.7 "我们比对手快"到底值多少（`python -m train.race`）

上一节的结论容易被误读成"提速没用"。准确的说是：**提速的收益是相对量，
只在对手也来抢同一个球时兑现。** 单狗计时（`train/race.py`，含指令延迟与一阶惯性）：

| 档 m/s | 1.5 m 球 | 3.0 m 球 | 5.0 m 球 | 相对 0.45 的速度 |
|---|---|---|---|---|
| 0.45 | 2.55 s | 5.90 s | 10.00 s | 1.00× |
| 0.68 | 1.75 | 4.00 | 6.70 | 1.48× |
| 0.90 | 1.35 | 3.05 | 5.10 | 1.93× |
| 1.22 | 1.05 | 2.30 | 3.80 | 2.57× |
| 1.48 | 0.90 | 1.90 | 3.15 | 3.11× |

带距离劣势（对手距球 1.5 m、0.45 档）：

| 我方档 | 我方最多还能离球 | 距离比 | 纯匀速理论比 |
|---|---|---|---|
| 0.90 | 2.50 m | 1.67 | 2.00 |
| 1.22 | 3.30 m | 2.20 | 2.70 |
| 1.48 | 3.90 m | 2.60 | 3.30 |

也就是 **快 2 倍 = 可以比对手晚出发 1.67 倍距离还先到**（理论 2.0，起步惯性吃掉 17%）。
救球场景（球被弹到侧前方 1.5 m、双方等距 1.6 m）：0.90 档赢 1.95 s，1.48 档赢 2.75 s。

这些收益落在多少时间里？用基线策略实测：**半场里有 35.4% 的步数"无人处于 0.43 m
触球圈"**（4 min 里约 85 s 是散球争抢）——那就是速度能兑现的全部窗口，剩下 65%
的时间是"有人在控球"，比的是控球质量而不是速度。

三条判据：

1. **对手 ≤0.4 m/s**：我们 0.45 已经稳赢每一次争抢 → 提速增量 ≈ 0（E 5.00 vs 4.90 就是这么来的）。
2. **对手 0.6~0.9 m/s**：3 m 球的胜负线在这里 —— 我们 0.90 对 0.68 领先 0.95 s、
   对 0.90 打平、对 1.22 落后 0.75 s。这种对手下提速才是真收益。
3. **短冲不是"跑得快"**：触发条件要求球在 0.9 m 内，它是"射门/一脚出球"，救不了远征。

所以判断要不要提速，先问一句：**赛事里对手大概多快？** 对手慢就维持 0.45 把球控好；
对手快（或者你打算用速度去压迫）就上 0.90，但必须同时解决 14.4 的自伤死球。

## 15. 仿真保真度审计：这套训练能替代真机吗（2026-11-17）

结论分三层，**不要一句话答"能/不能"**：

| 层 | 可信度 | 依据 |
|---|---|---|
| **契约层**：观测布局、动作缩放、规则判定 | **高** | 训练与部署同一份公式，`verify` 实测 max\|Δ\|=0；场地 10×5.5、门线 4.585、门宽 1.5、死区 0.8、僵持 8 s 与规则一致 |
| **决策层**：奖励形状、信息价值、角色分工、战术倾向 | **中高** | 只对"仿真内部的相对比较"有效（本 README 的消融/奖励结论都在这一层），不能外推到绝对战绩 |
| **执行层**：动力学、接触、时序 | **低** | 纯运动学 + 弹性碰撞，下面三条是能量化的偏差 |

### 15.1 三条可量化的偏差

1. **球出脚速度高估约 1.5 倍**。仿真把"狗-球接触"当弹性碰撞：出脚速度 = (1+e)·v_dog，
   e∈[0.3,0.7] → 1.3~1.7 倍狗速。实机是**持续接触推球**，球最多到机身速度（§17.5 的
   估算假设）。同一件事的对照：仿真短冲实测出脚 2.19 m/s、滚 3.55 m；§17.5 对实机
   push 的估算是 1.38 m/s、滚 2.27 m —— 速度 1.6×、距离 1.56×。
2. **转向响应偏快**。仿真 `tau_w=0.10~0.30 s`；而部署端 `Config.turn_response_grace=1.0`
   （换向后最多等 1 秒才判断"是否真的转过来了"）。这个参数本身就是"实机换向慢"的证据。
3. **起步没建模**。仿真从静止 50~150 ms 就有速度；实机要先起振步态，`gait_kick_action --push`
   的标准流程是"先走 250 ms 再发力"。

### 15.2 完全没建模的

腿/步态（步高、相位、抬脚）、打滑与地毯摩擦、摔倒与姿态保护（实机有 `stand_guard`）、
电量下降与过热降速、球旋转（马格努斯）、球-围挡/门柱反弹、狗的身体形状（现在是
半径 0.16 m 的圆，实机约 0.6×0.3 m）、两狗缠腿/互相顶翻（现在只做位置分离、不改速度）、
动捕断流的时间相关性（现在是独立丢帧，实机是成段丢失）、裁判暂停与 15 s 复位、
ROS/网络丢包。

### 15.3 这些偏差具体会怎么骗你

- **可以信的**：走位方向、什么时候该射、要不要传球、队友槽位值不值 6 维、奖励项该不该开。
- **不能信的**：绝对进球数、死球次数、"几秒能到球"、球能滚多远、上机胜率。
- **一个具体的坑**：仿真里球比实机跑得远 → 策略会练出"追得更猛"的习惯；实机上球
  停得更近，同样的策略容易冲过头、把球顶飞。上一轮"高速档死球翻倍"的结论方向
  大概没错，但**倍数被高估了**。

### 15.4 标定路径（工具已就绪）

```bash
# 1) 先验拟合器：合成数据反解出已知的 2 帧 / 0.15 s / 0.95 增益，全中
python -m train.calibrate --self-test

# 2) 实机录 30~60 s：直走→停→直走（台阶）+ 正弦转向（相位）
ros2 run pkg_soccer record_motion --ros-args -p output:=/abs/path/id.csv

# 3) 拟合并给出应写回 EnvConfig 的 latency / tau / tau_w
python -m train.calibrate /abs/path/id.csv
```

球-狗出脚那一条没法从这条 CSV 得到，要单独做个小实验：球摆固定位置，狗以
0.2 / 0.45 / 0.8 m/s 各推 10 次，用动捕量"出脚速度"和"滚到静止的距离"，
反推 `ball_restitution` 与 `ball_drag`（现在的 0.3~0.7 / 0.3~1.2 全是猜的）。

顺序建议：**先标定 → 再重训 → 影子模式（`enable_motion:=false`）→ 0.2 限速上机**。
不标定直接训，等于把三次猜测（延迟、惯性、球弹性）叠在一起当真相。

## 16. 提速档长训：sp_h / sp_i（2026-11-17 实跑）

### 16.1 sp_h：500 万步自博弈（0.90 档 + 门控短冲）

```bash
python -m train.train_ppo --role attacker --obs-dim 41 \
  --speed-scale 2.0 --dash --dash-goal-cone 0.9 \
  --init runs/sp_e/policy.npz \
  --peer-teammate runs/sp_e/policy.npz --peer-opponents runs/sp_e/policy.npz \
  --steps 5000000 --envs 8 --out runs/sp_h
```

约 1250 步/秒，全程 70 分钟。评估（`eval_match`，3 种子 × 2 半场，脚本对手 0.30 m/s）：

| 权重 | 进球/场 | 失球/场 | 死球/场 | 控球率 | 触球/半场 | 球均 x | 狗-球均距 |
|---|---|---|---|---|---|---|---|
| `sp_e`（300k，起点） | **13.7** | 0.7 | 73.3 | 44.6% | 130 | +1.83 m | 1.47 m |
| `sp_h`（5M，自博弈） | 6.7 | **0.0** | **42.7** | 66.2% | 102 | +1.46 m | 1.05 m |

**结论：死球降 42%，但进球腰斩，属于"退化"而非"变强"。** 特征很典型：控球率从 45% 涨到
66%、贴球更紧（1.05 m），但触球次数和球的前向位置都下降 —— **学会了抱住球不丢，而不是推进射门**。
原因是训练对手就是自己（零和博弈里"控住"比"冒险推进"更划算），而评估对手是 0.30 m/s 的脚本，
"控球"在它面前没有收益。

### 16.2 sp_i：换对手强度 + 远离死区势能项

针对上面两个成因各改一处：

| 改动 | 理由 |
|---|---|
| 去掉 `--peer-*`，改用脚本对手 | 自博弈让策略只会"控住"，对弱对手不进球 |
| `--scripted-speed 0.60`（新增参数） | 0.30 m/s 的脚本太慢，学不到对抗下的推进 |
| `--reward-edge 1.0`（新增） | 势能项 `Φ += w × min(1, 球到最近危险边界距离)`，把球从边线拉回来而不改最优策略 |
| `--init runs/sp_h/policy.npz` | 保留"低死球"的习惯，只修"不推进" |

```bash
python -m train.train_ppo --role attacker --obs-dim 41 \
  --speed-scale 2.0 --dash --dash-goal-cone 0.9 \
  --init runs/sp_h/policy.npz --scripted-speed 0.60 --reward-edge 1.0 \
  --steps 3000000 --envs 8 --out runs/sp_i
```

**评估口径必须与训练一致**：`eval_match --scripted-speed 0.60 --speed-limit 1.0`。
`--speed-limit` 尤其关键——0.90 档满舵对角模长 0.985，限速给 0.9 会裁掉 8.6% 的指令，
而训练用的是 1.0（`0.50 × speed_scale`）。

### 16.3 sp_i 实测：进攻回来了，但防守塌了

对手统一 0.60 m/s、限速 1.0、3 种子 × 2 半场：

| 权重 | 进球/场 | 失球/场 | 净胜 | 死球/场 |
|---|---|---|---|---|
| `sp_e`（300k 基线） | 9.0 | **1.0** | **+8.0** | **90.7** |
| `sp_h`（5M 自博弈） | 2.0 | 1.0 | +1.0 | 47.7 |
| `sp_i`（3M 混合对手） | **12.3** | 5.7 | +6.6 | 100.0 |

`sp_i` 进球涨 37%，但**失球从 1.0 涨到 5.7**，净胜反而低于 `sp_e`。

原因不是"变弱"，而是**训练/部署形态不一致**：`sp_i` 训练时同队另一只跑脚本 `support`
（守位、不压上），而部署端两只狗跑的是**同一份权重**（都会压上），于是后场空掉。
`sp_h` 反而没这个问题（它就是"队友=自己"训的，失球恒为 0），代价是进攻退化。

**这条比数字更重要**：比赛里两只狗各跑一份同样的 `policy_team_*_actor.npz`，
所以训练时必须让 `--peer-teammate` 也用同一份权重，否则评估和实战都会出现
"两狗同时前压"的后防空档 —— 而这在训练里根本看不到。

### 16.4 三轮都输给基线，根因是乌龙球

`sp_j`（队友=自己、对手=`sp_e`、`reward_edge 1.5`，300 万步）结果更差：

| 权重 | 进球/场 | 对方进球 | 其中**乌龙** | 净胜 | 死球/场 |
|---|---|---|---|---|---|
| `sp_e` | 9.0 | 1.0 | **0.0** | **+8.0** | 90.7 |
| `sp_h` | 2.0 | 1.0 | 0.0 | +1.0 | 47.7 |
| `sp_i` | 12.3 | 5.7 | **4.5（100%）** | +6.6 | 100.0 |
| `sp_j` | 11.7 | 7.7 | **3.5（100%）** | +4.0 | 86.3 |

关键数字是"乌龙占比 100%"：`sp_i`/`sp_j` 的失球**全部**是"我方最后触球后球进自家门"，
不是被对手打进的。`sp_e` 一次都没有。

**为什么会这样**：面对 0.6 m/s 的对手，正面对抗抢不过，长训会收敛到"侧向捅球"
（从侧面把球捅开），而侧向捅球不控制出球方向 —— 在自家半场就是乌龙。
`sp_e` 只训了 30 万步、没学到这个策略，所以侥幸没有。**这不是"sp_e 更强"，
而是"sp_e 还没学会这个坏习惯"**。

同理，`sp_h` 的"抱球退化"也是长训的产物：自博弈里"控住球不丢"比"冒险推进"更划算。

三条可执行结论：

1. **提速训练必须显式惩罚乌龙**。现有 `reward_concede=-10` 太稀疏（一次半场 600 步里
   只有几次），不足以压住"侧向捅球"的即时收益。做法：在 `last_touch` 属于我方且
   球速指向我方门时，给一个稠密的小惩罚（例如 `-0.02/步 × 球朝我方门的接近速度`），
   或者干脆在自家半场给触球加负奖励。
2. **仿真高估球速约 1.5 倍**（§15.1），实机乌龙风险比仿真更高，所以这条不能靠"上机再调"。
3. **0.45 档 + 无短冲仍是唯一有 5 球/半场证据的配置**（§14.3 旧基线）。0.90 档目前的
   净胜来自"进球多"，一旦乌龙计入真实比分就全部归零。


## 17. 方向感：让球朝对方门滚，而不是朝边线（2026-11-17）

### 17.1 先量出来：基线根本没有方向感

`train/aim.py` 统计"球被推出去时朝哪"，直接量这件事（不是看进球数）：

```bash
python -m train.aim --model pkg_soccer/policy_team_attacker_actor.npz \
    --dash --speed-limit 1.0 --halves 2
```

`sp_e` 的基线（2 半场，脚本对手 0.60、球速 >0.3 m/s 的步）：

| 指标 | 数值 | 含义 |
|---|---|---|
| 朝门角中位 | **89°** | 球速与"球→对方门"几乎垂直 —— 全是横向捅球 |
| 射正率 | **11.5%** | 夹角 <20° 的步数占比 |
| 朝己方门占比 | **48.1%** | 接近一半的推球是朝自家门方向 |
| 朝门投影 | +0.11 m/s | 有球速时的平均前向分量，接近 0 |

### 17.2 观测里早就有"威胁方向与范围"

41 维观测的 23-28 槽是最近对手的 **6 维：机身系相对位置（2）+ 相对速度（2）+ 相对朝向 sin/cos**，
29-34 和 35-40 是队友与次近对手的同样 6 维（`train/obs.py::body_block`）。
也就是说"对手多快、朝哪跑、离我多远"策略**一直看得到**，缺的不是信息，是**奖励没有告诉它往哪边推**。

所以本轮不改观测维度（改了旧权重全废、部署端要同步改），只加两个奖励项：

| 参数 | 含义 | 量级（600 步一集） |
|---|---|---|
| `--reward-aim` | 球速在"球→对方门"上的投影 × DT，正向奖励 | 0.08 → 0.9 m/s 推满一集约 +2.2 分 |
| `--reward-own` | 球速在"球→**自家**门"上的投影 × DT，负值惩罚 | −0.5 → 反向推满一集约 −10 分 |

配合已有的 `--reward-edge`（球到边线的势能项），三项分别管"朝哪推 / 别往自家推 / 别靠边"。

### 17.3 为什么不用"对手拦截点"这种显式特征

"对手的威胁范围"本质是"对手能不能先到某个点"，策略从相对速度+相对位置就能推出来，
而 PPO 的 MLP 学这个映射并不难。显式加特征要改观测维度（41→45+），代价是：
旧权重全废、`rl_control.observation` 与 `train/obs.py` 要同步改、`verify --contract`
要重写、部署端要重测。**先证明"加奖励就能学会"，再考虑要不要加特征。**

### 17.4 第一次尝试（sp_k2）失败：奖励"球速方向"没有杠杆

从 `sp_e` 热启动 300 万步，`--reward-aim 0.25 --reward-own -0.6 --reward-edge 1.0
--shaping-stage 1.6 --shaping-ball 1.8`，结果方向感**反而变差**：

| 权重 | 朝门角 | 射正率 | 朝己方门 | 朝门投影 |
|---|---|---|---|---|
| `sp_e` | 78° | 14.1% | 40.3% | +0.35 m/s |
| `sp_k2` | **94°** | **8.4%** | **54.5%** | −0.06 m/s |

原因是**因果链断了**：球一旦被撞出去，方向由碰撞法线（= 狗的运动方向）决定，
狗在球滚动的那 0.05~0.2 s 里根本改不了它。奖励"球速朝门"等于奖励一个已经
无法影响的结果，PPO 拿不到有效梯度，只在噪声里漂移。

### 17.5 诊断：问题在"碰球的位置"，不在"推的方向"

统计触球瞬间狗相对"球→对方门"的投影（负=在球后方，正确；正=在球前方，只会把球顶回去）：

| 权重 | 球后方（正确） | 侧面 | 球前方（错误） |
|---|---|---|---|
| `sp_e` | 53% | 8% | **39%** |
| `sp_k2` | 40% | 12% | 48% |

**接近四成的触球发生在球的前方** —— 球在我与自家门之间，我迎上去只能把它顶回去。
这才是"没有方向感"的物理源头，也是乌龙和横向捅球的来源。

### 17.6 `--reward-front`：直接罚"坏触球"

在 `_ball_collisions` 里判定：若狗在球的球门一侧（`-(normal·u) > 0.05`），
本步记一次坏触球，`_reward` 里按队扣 `reward_front`（建议 −0.4 ~ −0.8）。

| 参数 | 量级 |
|---|---|
| `--reward-front -0.5` | 半场约 15~25 次坏触球 → −7.5 ~ −12.5 分，与进球（10 分）同量级 |

这是**事件型、归因明确**的信号（谁碰的、在哪个位置碰的一清二楚），
比"球速方向"更适合 PPO —— 它发生在决策的当步，不存在跨步信用分配问题。

`sp_m` 的配置：`--reward-front -0.5 --reward-aim 0.15 --reward-own -0.4
--reward-edge 1.0 --shaping-stage 1.2`，从 `sp_e` 热启动 300 万步。

### 17.7 真正的原因：球被弹飞了，不是狗没方向感

`sp_m`（坏触球惩罚）、`sp_n`（坏触球罚 + 好触球奖）都试过，结果一致：
训练后"球后触球"从 64% 掉到 48%，方向感更差。三次奖励塑形的方向都失败了。

回头查物理：`_ball_collisions` 是**弹性碰撞**，出球速度 = (1+e)·狗速在法线方向的分量，
`e` 默认随机 0.3~0.7 → 球速是狗速的 1.3~1.7 倍。球一下飞出去，狗没有任何机会
在球滚动时改变方向。**"没有方向感"的根源是球根本不听使唤**，而 §15.1 早就写明
"仿真高估出脚速度约 1.5 倍，实机是持续接触推球"。

验证：**同一份 `sp_e` 权重，只改球物理、不训练**：

| 球物理 | 朝门角 | 射正率 | 朝己方门 | 进球 | 死球 |
|---|---|---|---|---|---|
| 默认（e=0.3~0.7，drag=0.3~1.2） | 78° | 14.1% | 40.3% | 5.0 | 44.5 |
| 持续接触（e=0.15，drag=1.2） | **64°** | **17.4%** | **24.4%** | **7.5** | **31.0** |

一个参数都没调策略，指标全面变好。所以之前的"方向感差"有相当一部分是**仿真失真**，
不是策略缺陷；用奖励去修一个物理造成的现象，当然修不动。

新增两个参数（评估/训练都要对齐）：

```bash
--ball-restitution 0.15    # 球-狗碰撞恢复系数（默认随机 0.3~0.7）
--ball-drag 1.2            # 球滚动阻尼 1/s（默认随机 0.3~1.2）
```

`train.aim` / `train.eval_match` 也支持这两个参数，**评估必须与训练同值**，
否则数字不可比。真机标定方法见 §15.4（球摆固定位置、狗以 0.2/0.45/0.8 m/s 各推 10 次，
量出脚速度与滚动距离反推 e 和 drag）。

`sp_p` 就是在这套物理下从 `sp_e` 热启动重训的（300 万步，奖励只保留 `--reward-back 0.2
--reward-edge 1.0`，不再叠加方向类稠密项 —— §12.1 的教训：稠密项总量别超过进球奖励）。
