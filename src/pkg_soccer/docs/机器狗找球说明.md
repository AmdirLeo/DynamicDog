## 1. 这个程序做什么

用动捕系统追踪球的坐标，并让机器狗走过去，到球前 `--stop-distance`（默认 0.40 m）停下。

| 子命令 | 作用 | 是否让狗动 |
|---|---|---|
| `watch` | 只打印**狗坐标 / 球坐标 / 球相对狗的前向-侧向-距离-方位 / 球速** | **不动**（不发速度） |
| `find` | 10Hz 闭环：姿态确认 → 原地转向对准球 → 前进 → 到距停车 + 语音 | 会动 |
| `check` | 只读自检：动捕位姿、速度指令、运动状态/站立服务、安全传感器 | 不动 |

**不包含踢球**（扩展见 §11）。

## 2. 参考了 DynamicDog 的哪些实现

| 参考文件 | 采用的模式 | 本程序对应 |
|---|---|---|
| `racing7.py` | VRPN `/vrpn/<刚体>/pose` + 10Hz `MotionServoCmd`（motion_id=308 足球步态）；**用 roll 当航向 + 每只狗固定角度偏置**；`toward()` 分级转向；距离分级速度；`vy` 横向微调 | `--yaw-axis`/`--yaw-offset`、`--motion-id`、分级速度/转向 |
| `pkg_soccer/control.py` | 位姿**同坐标系 + 接收时间新鲜**校验；连续帧确认再起步；`turn_rate()` 容差外最小 0.20 rad/s；`drive_to()` 前进速度随距离减小（下限 0.04）；球速跟随；转向反向/无进展保护 | `observation()` 帧检查、`confirm_samples`、`turn_rate()`、`_control()`、`TurnMonitor` |
| `pkg_soccer/measurement.py` | `Track` 用**接收时间差分**估计球速，拒绝断流/跳点/超速 | `VelocityTracker`、`--lead-time` 预测 |
| `pkg_soccer/stand_guard.py` | `motion_status` 姿态门控；坐/趴时用 `motion_result_cmd` **只请求一次** `111` 站立，站稳后才走；故障锁停 | `StandGate`、`--stand-timeout`、`--no-stand-guard` |
| `src/pkg_1016/move.py` | `motion_id=303 / cmd_type=1 / value=2 / step_height=[0.05,0.05]` 10Hz 发布 | `publish_velocity()` |
| `soccer.py` | 结束帧用 `MotionServoCmd.SERVO_END` 退出 servo | `end_motion()` |

没有照搬的：RL 策略（`.npz`）、足球场/球门坐标、绕球/射门状态机、多狗协同。找球只需要"追到球前"。

## 3. 运行前提

### 3.1 动捕（必须）

1. 动捕电脑启动 FZMotion，完成标定，**给狗和球各建一个刚体**，开启 VRPN 导出：
   - 导出选 **Z-up**（软件自动绕 X 轴转 90°：X 不变、Z 向上、Y = 负的软件旧 Z 方向）；
   - VRPN 端口默认 **3883**；本实验室动捕电脑 IP `10.0.0.252`；
   - 建狗刚体时让**狗头朝 +X**（否则 yaw 有固定偏差，可用 `--yaw-offset` 补）。
2. 机器狗上启动 VRPN 转发（`vrpn_client_ros2`）：

```bash
cd vrpn_client_ros2
source /opt/ros2/cyberdog/local_setup.bash
source install/local_setup.bash
ros2 launch vrpn_listener sync_entity_state.launch
```

3. 确认话题（本机实测见 `topic_list.txt` 末尾）：

```bash
ros2 topic list | grep vrpn
# /vrpn/Lizj_dog/pose    <- 狗
# /vrpn/ball/pose        <- 球
ros2 topic echo /vrpn/ball/pose --once
```

> 刚体名不是 `Lizj_dog` / `ball` 时用 `--dog-body` / `--ball-body` 指定。

### 3.2 姿态/站立服务（建议）

`/<dog>/motion_status`（`protocol/msg/MotionStatus`）与 `/<dog>/motion_result_cmd`
（`protocol/srv/MotionResultCmd`）。程序用它们判断"狗是否站着"：坐/趴时请求一次
`motion_id=111` 站起，站稳后才发速度。没有这些接口时程序等 `--status-timeout` 秒后
跳过门控并告警；**确保狗已经站着**再用 `find`（或加 `--no-stand-guard`）。

### 3.3 安全传感器（可选）

`/<dog>/scan`、`/<dog>/ultrasonic_payload` 做**前向安全停车**（≤ `--obstacle-stop-distance`）。
没有数据时只告警、不阻断。

## 4. 快速开始（按顺序，别跳步）

```bash
# 1) 自检（只读，不会让狗动）
python3 FindBallDemo.py check

# 2) 只追踪球坐标/球速（核对坐标与方位，不发速度）
python3 FindBallDemo.py watch

# 3) 演练：算控制但只打印速度指令
python3 FindBallDemo.py --dry-run find

# 4) 小速度真机（空旷场地，手边急停）
python3 FindBallDemo.py --max-speed 0.15 --stop-distance 0.40 find

# 5) 正常速度（默认 0.30 m/s）
python3 FindBallDemo.py find
```

`watch` 打印示例（每秒 2 条，`--print-hz` 可调）：

```
狗(x=1.00, y=2.00, yaw=0°) | 球(x=2.50, y=2.20) | 相对: 前=1.50 左=0.20 | 距离=1.51 m 方位=8° | 球速=0.00 m/s | 姿态=READY
```

### 4.1 航向不对时先校准（参考 racing7 的做法）

如果 `watch` 里"方位"随球移动变化很小/方向不对，或 `find` 里狗转向方向反：
1. 让球放在狗**正前方**，记下打印的 `yaw`；
2. 把狗头转到世界 +Y 方向，再记 `yaw` —— 应增加约 90°；
3. 不对就换轴：`--yaw-axis roll`（DynamicDog racing 实测用 roll）或 `pitch`；
4. 还有固定偏差就补 `--yaw-offset <度>`（例如 racing 里每只狗有 48° 偏置）。

参考命令：

```bash
python3 FindBallDemo.py --yaw-axis roll --yaw-offset 48 watch
python3 FindBallDemo.py --yaw-axis roll --yaw-offset 48 --dry-run find
```

> `find` 有转向无进展保护：持续转向 3 秒但动捕航向不变会停车并提示检查
> `--yaw-axis/--yaw-offset`（`--turn-timeout 0` 可关闭）。

## 5. 坐标约定与算法

### 5.1 世界坐标系（PPT slide 34/37）

- 动捕软件默认 Y-up；**导出 ROS2 选 Z-up**：Z 向上、X 不变、Y = 负的软件旧 Z 方向；
- 标定板短边 = X 轴、长边 = Z 轴；狗刚体建立时**狗头朝 +X**；
- 狗位姿 `(x, y, yaw)`：`yaw` 绕世界 Z 轴，**逆时针（+）= 左转**；
- 四元数 → 欧拉角（slide 52），本程序支持取 `yaw/roll/pitch` 任一分量当航向，再加偏置。

### 5.2 球相对狗的坐标

```
dx = 球x - 狗x,  dy = 球y - 狗y
前向 forward =  cos(yaw)*dx + sin(yaw)*dy      # >0 球在狗前方
侧向 lateral = -sin(yaw)*dx + cos(yaw)*dy      # >0 球在狗左侧
距离 distance = hypot(dx, dy)                  # 水平距离（米）
方位 bearing = atan2(lateral, forward)         # + 左，(-π, π]
```

### 5.3 球速与预测（参考 measurement.py）

- 用**收到消息的本地时间差**估计球速 `(vx, vy)`；
- dt > 0.5 s（断流）或位置跳变超过 `12 m/s × dt + 0.05` 时判为无效，不参与预测；
- `find` 用 `--lead-time`（默认 0.15 s）预测球的位置作为**前进方向**，距离仍按实际值判断，
  所以滚动球也能跟；`--lead-time 0` 关闭预测。

### 5.4 控制律（`find`）

| 情况 | 速度指令 `vel_des=[vx, vy, wz]` |
|---|---|
| 球距离 ≤ `--stop-distance` | `[0, 0, 0]` 停车（语音"可以踢球了"） |
| 前方障碍 ≤ `--obstacle-stop-distance` 且不是球本身 | `[0, 0, 0]` 安全停车 |
| `|bearing| > --align-tolerance`（默认 0.25 rad ≈ 14°） | `[0, 0, wz]` 原地转向；`wz = sign·min(max_yaw, max(0.20, 1.5·|bearing|))` |
| 其余 | 朝预测球方向前进：`vx = 0.8·(distance-stop)` 限幅到 `[0.04, max_speed]`；`wz` 小修正；`--max-vy>0` 时允许侧移微调（默认 0） |

- 到球/超时/Ctrl+C：先发零速数据帧，再连发 3 帧 **`SERVO_END`**（`cmd_type=0`）退出 servo；
- 起步前要求连续 `--confirm-samples`（默认 3）帧有效位姿，避免用旧帧启动。

### 5.5 姿态门控（参考 stand_guard.py）

1. `motion_status` 显示 `motion_id ∈ {111,112}` 或当前行走步态 → 允许走；
2. 显示坐/趴（`101`/`143`）→ 调 `motion_result_cmd` 请求**一次** `motion_id=111`，
   等状态变为站立；超过 `--stand-timeout`（默认 25 s）失败停车；
3. 状态报错（`switch_status` 非 0/1、ori/foot/motor error）→ 直接停车，不自动重试；
4. 一直收不到 `motion_status` → 等 `--status-timeout`（默认 1 s）后告警并跳过门控。

### 5.6 丢失与安全

- 狗/球位姿超过 `max(--lost-timeout, 0.5)` 没更新 → 发零速并打印"等待动捕位姿..."；
- 狗/球位姿 `frame_id` 不一致 → 按无观测处理（只告警一次）；
- 雷达/超声数据超过 `--sensor-timeout` → 视为没有安全数据，只告警（仍继续找球）；
- 雷达/超声看到的就是球本身（`|读数 - 球距离| ≤ 0.2 m`）→ 不误停。

## 6. 参数总表

| 参数 | 默认值 | 作用 |
|---|---|---|
| `--dog <前缀>` | 自动探测；失败用 `mi_desktop_48_b0_2d_5f_bd_98` | 机器狗话题前缀 |
| `--dog-body <名字>` | `Lizj_dog` | 狗在动捕里的刚体名 |
| `--ball-body <名字>` | `ball` | 球在动捕里的刚体名 |
| `--yaw-axis <轴>` | `yaw` | 航向取 `yaw`/`roll`/`pitch`（racing 用 roll） |
| `--yaw-offset <度>` | `0` | 航向偏置（现场标定，加到动捕航向上） |
| `--position-scale <系数>` | `1.0` | 动捕位置单位换算 |
| `--stop-distance <米>` | `0.40` | 到球停下距离（球心到狗刚体原点） |
| `--max-speed <m/s>` | `0.30` | 最大前进速度（首次上狗建议 0.15） |
| `--max-yaw <rad/s>` | `0.70` | 最大转向角速度 |
| `--align-tolerance <rad>` | `0.25` | 方位容差（≈14°，容差内不转向） |
| `--yaw-rate-min <rad/s>` | `0.20` | 容差外最小转向角速度 |
| `--turn-timeout <秒>` | `3.0` | 转向无进展多久后停车（0=关闭） |
| `--lead-time <秒>` | `0.15` | 按球速预测球位置的时间（0=不预测） |
| `--max-vy <m/s>` | `0.0` | 侧移上限（0=不侧移；参考实现 0.2~0.3） |
| `--confirm-samples <n>` | `3` | 连续多少帧有效位姿才起步 |
| `--obstacle-stop-distance <米>` | `0.35` | 前方障碍安全停车距离 |
| `--sensor-timeout <秒>` | `1.0` | 雷达/超声数据失效时间 |
| `--lost-timeout <秒>` | `0.8` | 动捕位姿丢失判定 |
| `--hz <Hz>` | `10.0` | 速度指令下发频率 |
| `--print-hz <Hz>` | `2.0` | 坐标/状态打印频率 |
| `--motion-id <id>` | `303` | 步态 id（可选 305/308；支持 `0x12F` 写法） |
| `--step-height <米>` | `0.05` | 抬腿高度（发布为 `[h,h]`） |
| `--no-stand-guard` | 关闭 | 跳过站立姿态门控 |
| `--status-timeout <秒>` | `1.0` | `motion_status` 断流判定 |
| `--stand-timeout <秒>` | `25.0` | 请求站立后的等待上限 |
| `--dry-run` | 关闭 | 只打印速度指令，不下发 |
| `--no-speak` | 关闭（默认语音开） | 关闭语音提示 |
| `--ignore-safety` | 关闭 | 关闭雷达/超声安全停车（危险，仅调试） |
| `watch --seconds <秒>` | 不限 | 追踪多久后退出 |
| `find --seconds <秒>` | `120` | 找球墙钟上限（0=不限） |

> 全局参数写在子命令前面：`--dry-run find`、`--yaw-axis roll find`；
> `--seconds` 是 `watch`/`find` 自己的参数，写在子命令后面。

## 8. 真机分步联调清单

1. `ros2 topic list | grep vrpn` 有 `/vrpn/Lizj_dog/pose`、`/vrpn/ball/pose`；
   `ros2 topic echo /vrpn/ball/pose --once` 有数据。
2. `ros2 topic list | grep motion_servo_cmd` 有话题；`ros2 service list | grep motion_result_cmd`
   有站立服务（没有也可用 `--no-stand-guard`，但要确保狗已站立）。
3. 空场地、狗站好、球放在正前方约 1 m：`python3 FindBallDemo.py watch`；
   球往左/右移动，确认"相对: 前/左"和"方位"跟着变、符号正确（球在左 → 方位为正），
   推一下球看"球速"是否变化。
4. 航向不对：按 §4.1 用 `--yaw-axis/--yaw-offset` 校准到"球在左 → 方位为正、左转"。
5. `--dry-run find`：确认速度方向正确（球在左 → wz 为正；距离远 → vx 大）。
6. `--max-speed 0.15 find` 慢速实测：狗应转向对准球 → 走到约 0.40 m 停下；
   观察结束时是否打印"找球完成"且无异常。
7. 正常速度 `find` 复测；每步异常都退回上一步。

## 9. 排错表

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `check` 说"狗/球位姿话题未发现" | VRPN 没启动 / 刚体没建 / 名字不对 | 启动 `vrpn_listener`；`ros2 topic list \| grep vrpn`；用 `--dog-body/--ball-body` 指定 |
| `watch` 打印"球位姿=无" | 球刚体被遮挡 / VRPN 没发球数据 | 检查动捕里球刚体可见、VRPN 勾选导出 |
| 狗原地转不前进 | 方位一直超容差，或前方障碍安全停车 | 看日志"安全停车：obstacle"→ 移开障碍或调 `--obstacle-stop-distance`；方位乱 → 校准航向（§4.1） |
| 转向方向反了/一直转 | 航向轴或偏置不对 | 换 `--yaw-axis`、补 `--yaw-offset`；程序 3 秒无进展会停车提示 |
| 出发前就报"姿态门控失败" | motion_status 报故障/非站立 | 检查狗姿态/错误码；确保已站立，或 `--no-stand-guard` 临时跳过 |
| 坐姿下 find 卡住 | 没有站立服务 | `ros2 service list \| grep motion_result_cmd`；手动/App 让狗站起，或 `--no-stand-guard` |
| 走到球前停得太远/太近 | `--stop-distance` 与狗刚体原点位置不匹配 | 按实际量一下刚体原点到球心距离，改 `--stop-distance`（0.30~0.50 试） |
| 到球后继续走/越过球 | 距离读数抖动或动捕延迟 | 适当加大 `--stop-distance`；检查球位姿是否正常 |
| 狗不走也不报错 | 速度指令接口缺失 | `ros2 interface show protocol/msg/MotionServoCmd`；重装 protocol 包 |
| 报"等待动捕位姿..." | 位姿超过 `--lost-timeout` 没更新 | 确认 VRPN 频率/网络；检查动捕机是否掉线 |
| 程序退出后狗还在走 | 手动 kill -9 等异常退出 | 正常退出会补零速 + SERVO_END；异常退出用遥控器/急停 |
| `unrecognized arguments` | 全局参数写在子命令后面 | 例：`--ball-body ball find`（不是 `find --ball-body ball`） |

## 10. 安全事项

1. **首次必须小速度 + 空旷场地 + 手边急停**（`--max-speed 0.15`），先 `watch` 核对坐标再 `find`。
2. 动捕看不到障碍物，程序只用雷达/超声做前向安全停车；**不会后退**，狗后方要留空间。
3. `--ignore-safety` 只在架空/垫高调试时用，正式演示不要用。
4. 动捕刚体被遮挡时位姿会停住/跳动，程序按超时/跳点剔除，但仍有延迟。
5. 与官方导航/跟随任务互斥（都占 `motion_servo_cmd`），演示前确认没有别的节点在发。
6. 姿态门控只处理"坐下/趴下 → 站起"；奔跑中摔倒等情况程序会因姿态变化停车，需要人工检查。

## 11. 作业扩展：找球并踢球

当前只做到"到球前 0.40 m 停下"。参考 `pkg_soccer/control.py` 的 KICK 状态：
到球后沿"狗→球"方向短促前冲，并用时间/行走距离/球移动距离任一条件结束：

```python
# 到球后（reached 分支）短促前冲触球；真机先架空试，速度/时长要小
for _ in range(3):
    self.publish_velocity(0.35, 0.0, 0.0)   # 不要超过 --max-speed 的上限设定
    self._sleep(0.1)
self.stop_velocity(3)
self.end_motion()
```

参考实现里踢球参数：`kick_speed=0.55 m/s`、`kick_duration=0.8 s`、`kick_travel=0.20 m`、
`ball_move_distance=0.15 m`、`kick_distance=0.38 m`；这些都需要现场标定。
也可以用 `motion_result_cmd` 的预置动作（若本机固件有"踢/前扑"类 `motion_id`）。
